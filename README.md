# 📊 Калькулятор юнит-экономики маркетплейсов

Data-driven веб-приложение на **Streamlit** для расчёта юнит-экономики товаров на
маркетплейсах (Ozon, Wildberries, Яндекс Маркет и др.). Считает выручку, комиссии,
логистику, рекламу, хранение, возвраты, налог, прибыль, маржинальность, ROI/ROMI и
точку безубыточности. Тарифы вынесены в конфиги и обновляются без изменения кода.

> Развитие исходного статического калькулятора (`index.html`, GitHub Pages):
> та же бизнес-идея, но с корректной моделью расходов, редактируемыми тарифами,
> сценариями, сравнением площадок и админ-режимом.

## Возможности

- **Главная** — ввод параметров товара, выбор МП и схемы, ручное переопределение
  тарифов, детализация расходов, ключевые метрики и графики.
- **Сравнение МП** — один товар на всех площадках одновременно.
- **Сценарии** — базовый / оптимистичный / пессимистичный / ручной (стресс-анализ).
- **Тарифы маркетплейсов** — служебный режим: правка ставок, источник, дата,
  комментарий, **история версий**.
- **Справка** — формулы, показатели, порядок обновления тарифов.

## Архитектура

```
app.py                 # точка входа, навигация Streamlit
configs/               # настройки: налоги, сценарии, категории, пути
  settings.py
calculators/           # бизнес-логика (без Streamlit)
  models.py            #   доменные модели (ProductInput, MarketplaceParams, UnitEconomics)
  engine.py            #   движок расчёта + точка безубыточности (бисекция)
  scenarios.py         #   применение сценариев
services/              # слой данных
  tariff_repository.py #   чтение/запись тарифов, история версий, резолвер параметров
utils/                 # форматирование чисел
ui/                    # интерфейс (страницы Streamlit)
data/tariffs/*.json    # тарифы МП (источник + дата + история)
sources/               # полуавтоматическое обновление тарифов (валидация, шаблон)
docs/UPDATING_TARIFFS.md
index.html             # legacy-версия для GitHub Pages (сохранена)
```

Разделение слоёв: **данные** (`data/`, `services/`) → **логика** (`calculators/`) →
**интерфейс** (`ui/`). Движок расчёта не знает о происхождении тарифов.

## Локальный запуск

Требуется Python 3.10+.

```bash
# 1. Виртуальное окружение (опционально)
python -m venv .venv && source .venv/bin/activate

# 2. Зависимости
pip install -r requirements.txt

# 3. Запуск
streamlit run app.py
```

Приложение откроется на http://localhost:8501

## Публикация в Streamlit Community Cloud

1. Запушьте репозиторий на GitHub.
2. На https://share.streamlit.io → **New app**.
3. Repository: этот репозиторий, Branch: `main`, Main file path: `streamlit_app.py`
   (значение по умолчанию, которое ищет Streamlit Cloud). Можно указать и `app.py` —
   оба файла являются рабочими точками входа.
4. Deploy. `requirements.txt` подхватится автоматически.

> Если при деплое возникает ошибка «streamlit_app.py не найден» — убедитесь, что
> в поле **Main file path** указан существующий файл (`streamlit_app.py` или `app.py`).

## Обновление тарифов

Тарифы — это данные, а не код. Меняйте их через страницу **«Тарифы маркетплейсов»**
(с фиксацией в истории версий) или правьте `data/tariffs/*.json`. Подробно —
в [`docs/UPDATING_TARIFFS.md`](docs/UPDATING_TARIFFS.md).

Проверить корректность всех тарифов:
```bash
python -m sources.fetch_tariffs
```

## Улучшения относительно исходного калькулятора

- Корректная модель возвратов через процент выкупа (отгрузка `1/b`, возвраты `(1−b)/b`).
- Логистика зависит от объёма/веса, а не от фиксированной таблицы в коде.
- Точка безубыточности считается численно и работает при любой структуре расходов.
- Тарифы вынесены из кода в конфиги с источником, датой и историей версий.
- Добавлены ROI/ROMI, сценарии, сравнение площадок, редактируемые статьи расходов.
